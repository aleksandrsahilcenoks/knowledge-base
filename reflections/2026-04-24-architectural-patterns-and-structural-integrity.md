# Reflection: Architectural Patterns and Structural Integrity

## Date

2026-04-24

## What I Learned

I learned that working code is not enough. A software feature should also have a structure that supports future change.

Design patterns are useful because they give names and shapes to recurring design solutions. They also help AI agents follow a known structure instead of inventing uncontrolled architecture.

## Most Important Idea

A pattern should be used when it solves a real design problem.

Using a pattern without need may make the code more complex. The pattern must be justified by the feature's variability, responsibility boundaries, or integration needs.

## Connection to My Project

For my course project, I need to select one feature from Assignment 3 and implement its business logic using a suitable pattern.

The best candidate is probably a feature where rules may change over time, because such logic can often be handled with the Strategy pattern.
