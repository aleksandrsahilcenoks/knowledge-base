# Object-Oriented Design — Introduction

## Summary

Object-oriented design is the process of planning a system of interacting objects to solve a software problem.

An object contains encapsulated data and procedures. Its interface defines how other parts of the system can interact with it.

## Main Design Concepts

### Abstraction

Abstraction hides irrelevant details to reduce complexity.

### Modularity

Modularity divides a system into smaller parts so they can be developed, understood, tested, and reused independently.

### Architecture

Architecture defines the structure of the system and the way its components interact.

### Refinement

Refinement improves the quality of a design by making it more detailed and precise.

### Information Hiding

Information hiding prevents unrelated modules from accessing internal details.

### Refactoring

Refactoring improves the internal structure of software without changing external behavior.

### Pattern

A pattern is a repeated solution to a recurring design problem in a given context.

## Design Quality Issues

Important design qualities include:

- decomposability,
- composability,
- understandability,
- continuity,
- protection from side effects.

## Subsystem Contracts

A subsystem should have a well-defined interface through which communication with the rest of the system occurs.

A contract should describe:

- type of contract,
- collaborators,
- classes involved,
- operations,
- message format.

## Design Principles

Good software design should support:

- extensibility,
- modularity,
- maintainability,
- reliability,
- reusability,
- robustness,
- security,
- usability,
- performance,
- portability,
- scalability.
